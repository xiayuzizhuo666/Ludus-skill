# 公众号文章写作

把一个主题写成可以直接进入排版和草稿箱的公众号文章。六阶段推进，标题、框架、成稿三个点必须让用户确认；不伪造作者、头衔、业绩或数据来源。

## 六阶段

### 阶段 01：选题定位

确认四件事：

- 读者是谁：职业、处境、最关心的问题。
- 文章承诺什么：读完能带走的一个判断、方法或清单。
- 角度是什么：与同题文章相比，新增了哪一层信息。
- 素材够不够：用户提供的经历、数据、案例；没有就标出来，不编。

完成标准：能用一句话写出“给谁、解决什么、为什么现在写”。

### 阶段 02：标题

给 5–10 个标题选项，覆盖不同机制：

- 利益型：读完能得到什么。
- 好奇型：留下一个具体缺口。
- 对比型：前后、得失、常见做法 vs 更好的做法。
- 数字型：有几个方法、几个坑、几步。
- 身份型：点名一类读者。
- 反常识型：挑战一个常见默认。

标题要求：具体、可验证、不夸大；不用“震惊”“必看”“封神”这类空词；不承诺文章里没有的东西。参考 `references/title-patterns.md`。

完成标准：用户选定一个标题，或明确让你代选并说明理由。

### 阶段 03：框架

从 `references/framework-templates.md` 选一个框架，先给结构，不写全文：

```text
标题：
开头钩子：
第一部分：
第二部分：
第三部分：
结尾行动：
```

完成标准：用户确认结构，或提出修改后你已更新。

### 阶段 04：成稿

- 长度：2500–3000 字；用户指定长度时以用户为准。
- 开头：前三段内出现具体场景、冲突或问题，不写宏大背景。
- 主体：每一节只讲一个观点；观点后面跟例子、数字或可执行动作。
- 结尾：收回开头，给一个今天就能做的小动作；不喊口号。
- 语言：短句为主，专业名词当场解释；不用“赋能”“闭环”“抓手”这类空话。
- 事实：数字、案例、引语必须有来源；没有来源就删掉或标“待核”。
- 风格：从 `writing_style.md` 选一种；用户没指定时，根据主题推荐一种并说明理由。

完成标准：全文通读一遍，没有空段、没有编造、没有未解释的专业词。

### 阶段 05：保存

写入：

```text
<ARTICLES_DIR>/YYYYMMDD_标题关键词.md
```

文件头保留：

```markdown
# 标题

> 摘要：三行以内。
> 风格：温暖故事 / 专业干货 / 资讯日报 / 轻松幽默 / 锐评 / 人物访谈 / 复盘笔记
> 字数：
```

完成标准：文件存在，标题、摘要、风格、字数齐全。

### 阶段 06：配图提示词

写入：

```text
<ARTICLES_DIR>/YYYYMMDD_标题关键词_配图提示词.md
```

至少包含：

- 封面图 1 张：16:9 或 2.35:1。
- 正文信息图 2–3 张：每张只表达一个观点。
- 结尾引导图 1 张（可选）：1:1。

提示词写法见 `references/image-prompt-guide.md`。生成图片前必须让用户确认费用；没有 `ZHIPU_API_KEY` 时让用户手动配图或跳过。

完成标准：提示词文件存在，每张图有用途、尺寸、画面描述和禁止项。

## 硬规则

1. 不伪造作者身份、头衔、业绩、案例、引语或数据来源。
2. 不抄袭；引用他人观点要注明来源，改写要标“据……”。
3. 不写未经证实的医疗、法律、投资建议；需要时加“请咨询专业人士”。
4. 不使用真实个人隐私、客户名称、聊天记录截图；必须用时先脱敏。
5. 不写“AI 味”套话：不用“在这个快速变化的时代”“让我们一起”“总而言之”开头或收尾。
6. 不自动发布；只保存文章、提示词和 HTML，发布由用户在公众号后台完成。

## 自检

- [ ] 标题有 5–10 个选项，用户已选。
- [ ] 框架先给结构，用户已确认。
- [ ] 字数在 2500–3000 字，或符合用户指定。
- [ ] 每个数字、案例、引语都有来源，或已标“待核”。
- [ ] 没有伪造作者、头衔、业绩、数据。
- [ ] 风格与主题匹配，没有空话套话。
- [ ] 文章和配图提示词都已保存到 `ARTICLES_DIR`。
- [ ] 配图前已确认费用；没有密钥时已明确跳过或让用户手动配图。
